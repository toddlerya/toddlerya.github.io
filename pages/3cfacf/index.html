使用Docker部署Python开发调试运行环境

郭群 2020年07月07日 记录于此

# 一、背景

Python2已经寿终正寝了，对Python3没有需求的项目，可以继续用Python2维护，有Python3使用需求的项目，势必要迁移到Python3了。 但服务器目前自带的Python大多数还是Python2版本，少数有Python3的，也是Python3.5居多，想使用指定版本的Python3，有点难：

  • 因为我们内网环境，离线安装，编译，各种碰壁；
  • 而且直接升级服务器的Python版本，可能会给其他使用服务器的同学带来一定的麻烦；

为了环境的隔离和可迁移，我们应该使用Docker来解决这种问题。本文抛砖引玉，提供一个样例给大家参考。如有不当，欢迎指正。

# 二、思路

使用Python3的项目，多数是人工智能、数据分析治理相关的项目，为了更好的生态体验，我选择使用Debian10（buster)系统的Python； 比较新且相对稳定的Python版本为Python3.7，我选择Python3.7.7版本。

确立了镜像，接下来要考虑为镜像定制什么内容。

使用容器，我们期望每个容器的功能是单一的，这也是符合Docker的理念。因此我们的镜像定制原则为能少则少，一切从简。 为了能够方便使用，我们只增加两个程序：

  • sshd（更方便灵活的连接操作容器，比如使用PyCharm的远程调试功能等）
  • vim （便于直接修改容器内的文件，便于调试）

# （七）、使用定制的镜像启动容器

启动容器，开放22端口供ssh连接，挂载代码和相关用到的目录

docker run --name py3.7.7env -it --rm -v /etc/localtime:/etc/localtime:ro -v /home/qguo/AITestDBManager:/home/AITestDBManager qguo/py_env:3.7.7-buster_v1 /bin/bash
1

或者使用docker-compose启动
docker-compose.yml配置如下

version: "3"

services:
  py_env:
    image: qguo/py_env:3.7.7-buster_v1
    container_name: py3.7.7env_AITestDBManager
    stdin_open: true
    tty: true
    restart: unless-stopped
    networks:
      ait_net:
        ipv4_address: 192.147.1.2
    ports:
      - "2333:22"
    volumes:
      - /etc/localtime:/etc/localtime:ro
      - /home/qguo/AITestDBManager:/home/AITestDBManager
        
networks:
  ait_net:
    driver: bridge
    ipam:
      config:
        - subnet: 192.147.1.0/16
